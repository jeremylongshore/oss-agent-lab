**The last-mile gap between "trending repo" and "usable capability."**

# Operator-Grade System Analysis

## 1. Executive Summary

### Business Purpose

OSS Agent Lab is a capability factory built on the Claude Agent SDK (Python) that auto-discovers trending GitHub repositories from 7 data sources, scores them using 15 weighted signals on a 0-100 composite scale, and wraps top-scoring repos into 5 output formats. It eliminates the manual integration cycle that currently costs AI teams 3-5 days per repo.

The system is in active early development (v0.1.0) with 10 specialists implemented, a 4-layer agent architecture operational, and CI enforcing quality gates. The CLI commands are stubs — the real value is in the agent pipeline and scoring engine, both fully functional and tested. The project is MIT-licensed and intended as open-source infrastructure.

Primary risk is the 4 stub data sources (Reddit, DevHunt, Trendshift, The Rundown) — the scoring engine runs but only 3/7 sources return real data. Secondary risk is no caching or rate limiting on HTTP calls to external APIs.

### Key Data Flow

1. **Scoring:** 7 sources fetched in parallel (asyncio) → 15 signals weighted → composite score 0-100 → action threshold (auto_scaffold/evaluate/watch/skip) → temporal index stores time-series
2. **Query:** NL input → Conductor classifies intent via Claude API → Router matches capabilities → dispatches to N specialists in parallel → aggregates responses
3. **Output:** Each specialist's SKILL.md frontmatter → `generate_outputs.py` templates → 5 format files written to `output/`

### Dual Import Architecture

**Critical for operators to understand:** This repo has two import roots.

| Root | Install Method | Import Pattern | Contains |
|------|---------------|----------------|----------|
| `src/oss_agent_lab/` | `pip install -e .` | `from oss_agent_lab import ...` | Base classes, contracts, CLI |
| `agents/`, `scoring/`, `scripts/` | Direct (not installed) | `from agents.conductor.agent import ...` | All agent/scoring logic |

This means `agents/` and `scoring/` must be importable from the project root. CI does this by running from the checkout directory.

```bash
git clone https://github.com/jeremylongshore/oss-agent-lab.git
cd oss-agent-lab
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
```

```bash
pytest tests/                     # 136 tests, should all pass
ruff check . && ruff format --check .  # Lint + format
mypy src/                         # Type check
```

**Run the CLI:**
```bash
python -m oss_agent_lab           # Or: oss-lab
oss-lab run <query>               # NL query (stub)
oss-lab score <repo>              # Score repo (stub)
oss-lab specialists               # List specialists (stub)
```

**Score a repo programmatically:**
```bash
python -c "
import asyncio
from scoring.scorer import score_repo
score = asyncio.run(score_repo('karpathy/autoresearch'))
print(f'{score.repo}: {score.total}/100 -> {score.action}')
"
```

```bash
python scripts/generate_outputs.py agents/specialists/autoresearch/
```

**Scaffold a new specialist:**
```bash
python scripts/generate_specialist.py owner/repo --name my_specialist
```

### E. Error Handling Philosophy

All external calls follow the same pattern — **never propagate, always degrade gracefully:**

```python
try:
    async with httpx.AsyncClient(timeout=10.0) as client:
        response = await client.get(url)
        response.raise_for_status()
        return response.json()
except Exception:
    return {}  # sensible default, scoring continues with partial data
```

The Conductor returns a low-confidence fallback intent on API failure. The Router returns error responses for failed specialists but succeeds overall. The system never hard-crashes on external failures.
